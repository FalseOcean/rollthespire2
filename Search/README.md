## Maintaining game updates, RNG and model rules

Use this bounded route when a game update or a concrete counterexample changes prediction rules. Version policy belongs to PRODUCT_STRATEGY (internal record omitted); responsibilities and current evidence belong to PROJECT_ARCHITECTURE (internal record omitted) and CURRENT_STATUS (internal record omitted).

1. **Establish the actual baseline.** Record checkout/HEAD and existing edits, the resolved build reference and loaded `sts2` assembly identities, and release metadata provenance. Follow [BUILDING](../BUILDING.md) for `Sts2ReferenceDir`; retain binary path/hash and available assembly identity alongside source/decompilation provenance. A `GameSource` directory name alone does not identify the assembly. [GameVersionDetector](../Compatibility/GameVersionDetector.cs) prefers supplied runtime release information, then records its file fallback; an exact release version is not itself a binary hash or compatibility audit.

2. **Keep four identities separate.** Inspect [RuntimeVersionCompatibility](../Compatibility/RuntimeVersionCompatibility.cs) and [RuntimeProfileRegistry](../Compatibility/RuntimeProfileRegistry.cs): exact game identity, selected adapter `ProfileId`, RNG/generation `SemanticProfileId`, and compatibility confidence/blocked domains are separate fields. Registration or a model Match does not establish official support. Resolve the actual version through current code; do not invent a mapping or replace provisional reuse with an “all unknown versions reject” policy.

3. **Compare the affected mechanism.** Start with the corresponding source from the identified game binary, then trace canonical seed → root hash → named/event stream → draws. [ProfileSeedRules](../Compatibility/ProfileSeedRules.cs), the selected profile, [Core/Seed](../Core/Seed), and [Core/Rng](../Core/Rng) are the RT2 entry points. Check slot ownership, stream names, draw bounds/rounding, shuffle draw count and order, pool eligibility/cleaning/sorting, side effects and continuation cursors. A correct PRNG primitive cannot compensate for a changed pool or one extra draw; limit the investigation to actual dependents.

4. **Trace every affected consumer.** Representative entrances are [Beta111PredictionProfile](../Core/Prediction/Profiles/Beta111PredictionProfile.cs) for demand-scoped observations and [NeowSingleplayerReplay](FamilyExecution/NeowSingleplayerReplay.cs) for independent N filtering. Follow actual obtain effects and reward/route continuation into their owners, rather than forcing all consumers through a complete information document or treating an observation continuation as a full checkpoint.
