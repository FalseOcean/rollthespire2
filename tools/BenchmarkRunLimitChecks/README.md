# Explicit bounded benchmark checks

Run `dotnet run --project tools/BenchmarkRunLimitChecks -c Release` from the source root.
The runner links the actual production `SearchBenchmarkRunLimits` helper and checks default/empty process settings, a valid one-root range, the exact in-game comparison count 175842000896, the 2^40 limit, and rejection of invalid or culture-sensitive input. It also checks missing, valid and invalid UTF8 request files and process-setting precedence. Its one temporary test file lives below the tool's own `bin` directory and is deleted in `finally`; the original process environment is restored. It does not load Godot or start a search.

`RT2_BENCHMARK_SCAN_COUNT` is an explicit process-local test setting. When it is unset or empty, the UI also checks `RolltheSpire2/benchmark-scan-count.txt` below `Godot.OS.GetUserDataDir()`. This temporary request file supports games launched through Steam, which may not inherit a test shell's environment. Write only the invariant positive decimal count, without whitespace or a trailing newline, as UTF8. A nonempty process setting takes priority, including rejecting an invalid value rather than falling back to the file. An existing empty or invalid file prevents search startup; it never silently starts an unlimited run.

With no nonempty process setting and no request file, normal UI search retains `long.MaxValue` and the user's target count. When active, only the current request's count and match limit change; conditions, start seed, worker count and Exact preference remain unchanged. The effective match limit is `int.MaxValue`, not unlimited. The helper never deletes the request file. **Remove the temporary request file after the benchmark**, and clear any test process setting before regular continuation. Every new search while either setting is active uses the configured cap. Do not set either permanently or confuse a finite test with regular continuation.

Changing the request bounds can affect planning. Compare actual plan IDs/physical revisions, conditions, workers, Exact setting and complete committed ranges before interpreting timing. A manually cancelled baseline can also include an uncommitted GPU tail that a normally completed finite candidate run does not execute. One pair of measurements cannot establish a speedup.
